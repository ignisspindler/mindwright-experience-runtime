# Reading pilot transcripts

The pilot is qualitative. The aim is to learn what the controls actually feel like before building any measurement, so readers write notes, not scores.

## Before reading

- Work only in private storage. Never copy a transcript, a participant's words or any identifying detail into this repository.
- Read the participant's reflection first, then the transcript, then the manifest for that cell. Reading the manifest first makes it too easy to see what you expect.
- Note the cell's rung only after your first read.

## Four lenses

Write a few sentences under each. Quote short lines from the transcript in your private notes when they show something.

**1. Potency.** Did this work have force? Where was it alive, and where did it go slack? Would you want to read or play it again? What does the participant's reflection say about what stayed with them?

**2. Identity.** Without looking at the manifest, what do you think this work was doing? Then look: which attractors, invariants and secrets showed up, which were violated, and which were never tested by this path? At S0 and S1, what did the model do with so little?

**3. Divergence.** Compared with other plays of the same group, especially the same S3 cell in other harnesses: what did each model commit to concretely (people, places, forms, events)? Are they different performances of one work, variations on one story, or unrelated?

**4. Integrity.** Anything that broke the work:

- the first message acknowledged or summarized its instructions;
- sealed material or architecture names leaked;
- menus of choices, reassurance, lesson summaries, moralizing or rescue appeared;
- a consequence was undone or softened on request;
- characters, if any, all sounded like the narrator or existed only to help;
- something already established was contradicted;
- commentary was added to the ending, or the return block was altered, missing or placed inside the work;
- `END EXPERIENCE` failed, or an in-story wish to leave was treated as an exit;
- the model stepped out of the work when nothing required it.

## Per-transcript note (private)

```
Play / cell / harness / rung:
Potency:
Identity (before manifest):
Identity (after manifest): held / violated / untested
Commitments (what the model made concrete):
Integrity problems:
One line worth remembering:
```

## Aggregating

When a group's plays are read, write a short group note comparing its rungs and harnesses. Findings for `FINDINGS.md` are patterns across groups, written so that no participant can be identified. A quoted excerpt may appear only if that participant agreed to anonymized quotation.

When the same failure keeps recurring across models and groups, record it as a candidate for [`FORMALISM-LOG.md`](../FORMALISM-LOG.md), and try the cheapest fix first.
